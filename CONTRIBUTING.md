# Как мы работаем над Ирис

Нашли ошибку или придумали улучшение? Расскажите в issue, что случилось
или чего вам не хватает. Если уже есть правка, можно сразу открыть pull request.
Для уязвимостей есть [отдельный порядок](SECURITY.md).

## Одна задача — одна ветка

1. **Выберите базу.** Сейчас новые задачи начинаются от `origin/v0.9.1`.
   `main` пока показывает старую версию. После согласованного перехода
   базой для новых задач станет `origin/main`.
2. **Начните в отдельной ветке.** Короткое имя помогает найти работу,
   например `codex/fix-voice-stop`. Проверьте `git status --short --branch`.
   Если в папке уже есть незавершённые правки, можно создать отдельный worktree.
   Команды запускаются из текущего клона.

   ```powershell
   git fetch origin
   git worktree add -b codex/fix-voice-stop ../Iris-voice-stop origin/v0.9.1
   cd ../Iris-voice-stop
   ```

3. **Проверьте и сохраните изменения.** Посмотрите `git diff`, добавьте нужные
   файлы по именам и проверьте `git diff --cached`. Дайте коммиту имя по тому,
   что изменилось, например «Исправил остановку голосового ответа».
4. **Откройте PR, когда работу можно показать.** Отправьте ветку задачи
   и проверьте поле **base** в GitHub. Для обычной задачи сейчас это `v0.9.1`,
   а **compare** — ваша ветка. В описании напишите, что изменилось и как
   проверить. Если работа ещё идёт, подойдёт Draft PR.
5. **Слейте после ревью и проверок.** Вкладка **Files changed** показывает,
   что попадёт в базовую ветку, а **Checks** — результаты автоматических
   проверок. Для обычной задачи используем **Squash and merge**, чтобы в
   истории остался один понятный коммит. После слияния ветку задачи можно
   удалить, если её работа целиком перенесена и она больше не нужна.

Рабочее дерево — файлы в открытой папке. Ветка — указатель на последний
коммит своей линии работы. Worktree — отдельная папка с общим репозиторием
и своей веткой. PR предлагает перенести изменения между ветками.
Тег `vX.Y.Z` отмечает конкретный коммит выпуска, а версию приложения задаёт
[`VERSION`](VERSION). [GitHub Flow](https://docs.github.com/en/get-started/using-github/github-flow) ·
[Справка по worktree](https://git-scm.com/docs/git-worktree)

Посмотреть недавний граф коммитов можно командой
`git log --graph --oneline --decorate -20 origin/main origin/v0.9.1`.

Старые локальные ветки могут содержать незавершённую работу или прежнюю
историю с закрытыми ресурсами. Перед уборкой проверьте `git branch -vv` и
`git worktree list`. Ветка с пометкой `gone` может хранить локальные
коммиты. Для новой работы берите актуальную базу с GitHub.

## Подготовка и проверка

Выберите [профиль зависимостей](Docs/dependencies.md) и загляните в
[документ нужной подсистемы](Docs/index.md). Проверки зависят от изменений.
Для правок нескольких подсистем запустите из корня:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
npm --prefix apps/web test
npm --prefix apps/web run build
npm --prefix apps/desktop run check
.\.venv\Scripts\python.exe scripts/check_docs.py
.\.venv\Scripts\python.exe scripts/avatar_assets.py check-public
git diff --check
```

Для правок текста проверьте документацию, ссылки и оформление.
Перед отправкой проверьте содержимое коммитов и публичную границу аватара.
На PR GitHub проверяет документацию, backend, веб-сборку, оболочку Windows
и ресурсы аватара. Для установщика, живого микрофона и Unity предусмотрены
[отдельные проверки](Docs/release-runbook.md).

## Границы изменений

- Сохраняйте пользовательские данные и совместимость миграций.
- Управляемое ядро остаётся на loopback и требует временного токена.
- Coding Agent исполняет команды только в Docker.
- Сырой звук микрофона по умолчанию не сохраняется.
- SQLite остаётся каноническим хранилищем, индекс — перестраиваемым.
- Настройки публикуются после успешной записи.
- Версия приложения не заменяет номера схем и протоколов.
- Исправления жизненного цикла, хранения и конкурентного выполнения
  подтверждаются соответствующими регрессионными сценариями.

Для UI источник истины — [`design.md`](design.md) и
[`tokens.css`](apps/web/src/tokens.css). Анимации используют Anime.js v4.

Пользовательские изменения отражаются в [истории версий](CHANGELOG.md);
изменения контрактов — в документе подсистемы. Правила содержания и перевода
находятся в [редакционном руководстве](Docs/documentation.md).

## Что остаётся локально

Ключи, `.env`, пользовательские базы, журналы, записи микрофона, частные
модели и анимации, Unity-сборки, `node_modules`, Python-окружения и материалы
подписи остаются вне Git. Исследования храним отдельно от кода приложения
и помечаем как эксперименты.

Условия сторонних материалов проверяются независимо от лицензии кода;
см. [происхождение ассетов](THIRD_PARTY_ASSETS.md).
